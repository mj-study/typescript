## 커맨드 정의

```json
{
  "name": "ts-item",
  "description": "이펙티브 타입스크립트 아이템을 정해진 템플릿 형식으로 정리합니다",
  "hint": "아이템11 타입 체크와 잉여 속성 체크 구분해서 사용하기",
  "args": {
    "itemInfo": {
      "type": "string",
      "description": "아이템 번호와 제목 (예: 아이템11 타입 체크와 잉여 속성 체크 구분해서 사용하기)",
      "required": true
    }
  }
}
```

사용자가 `/ts-item 아이템11 타입 체크와 잉여 속성 체크 구분해서 사용하기`를 입력하면 다음 지침이 실행됩니다:

```markdown
# 이펙티브 타입스크립트 정리 작성

아래 템플릿에 맞춰 **{arguments}**의 내용을 정리해주세요.

## 파일 경로 및 이름
- 파일명: `src/section{챕터번호}/Item{아이템번호}.md`
- 예: `src/section1/Item11.md`
- 아이템 번호를 파싱하여 적절한 섹션에 파일을 생성하세요

---

## 문서 구조

### 필수 포함 요소

1. **제목 및 요약**
```markdown
# 아이템{번호}. {제목}

> {핵심 개념을 1~3줄로 요약}
> {추가 핵심 사항이 있다면 한 줄 더}
```

2. **주요 섹션들**
```markdown
## 1. {주요 개념 섹션 제목}
{개념 설명}

```ts
// 코드 예제
```

✅ {해당 섹션의 핵심 포인트}

## 2. {또 다른 주요 개념}
{설명}

```ts
// 예제 코드
```

### {세부 하위 개념이 필요한 경우}
```ts
// 상세 예제
```

✅ {핵심 포인트}
```

3. **핵심 정리**
```markdown
## 핵심 정리
> {전체 아이템의 핵심을 2~3줄로 요약}

{추가 중요 사항이나 주의점}
```

## 작성 가이드라인

### 1. 제목과 요약
- **제목**: 아이템 번호와 제목을 명확하게 표기
- **인용문 요약**: 문서 최상단에 `>` 기호로 핵심 개념을 1~3줄로 간결하게 요약
- 학습자가 파일을 열었을 때 바로 핵심을 파악할 수 있도록

### 2. 섹션 구성
- **논리적 흐름**: 기본 개념 → 심화 개념 → 실전 예제 순서로 구성
- **번호 매기기**: 주요 섹션은 `## 1.`, `## 2.` 형식으로 번호 부여
- **하위 섹션**: 필요시 `###`로 세부 개념 설명
- 섹션당 하나의 명확한 개념만 다루기

### 3. 코드 예제
- **언어 지정**: 모든 코드 블록은 ```ts로 타입스크립트 명시
- **주석 활용**: 코드 내 주석으로 핵심 설명 추가
- **실행 가능성**: 가능한 실제로 실행 가능한 코드 작성
- **대비 예제**: 잘못된 예제(에러 발생)와 올바른 예제를 함께 제시하여 차이점 명확화

### 4. 강조 표현
- **체크마크**: `✅` 기호로 각 섹션의 핵심 포인트 강조
- **에러 표시**: 에러가 발생하는 코드는 주석에 `// Error` 명시
- **OK 표시**: 정상 동작하는 코드는 `// ok` 또는 `// OK` 표시
- **X 표시**: 잘못된 접근은 `// x` 또는 `// X`로 표시

### 5. 핵심 정리
- 문서 마지막에 `## 핵심 정리` 섹션 필수
- 전체 내용을 2~3줄로 압축하여 인용문(`>`) 형식으로 작성
- 실무에서 반드시 기억해야 할 주의사항이나 팁 추가

### 6. 작성 스타일
- **간결함**: 불필요한 설명 지양, 핵심만 명확하게
- **예제 중심**: 이론보다는 실제 코드 예제로 설명
- **비교 설명**: "A vs B" 형식으로 차이점을 명확히
- **실용성**: 실무에서 바로 적용 가능한 내용 위주

### 7. 용어 사용
- 한글과 영문을 적절히 혼용 (예: "타입 공간", "값 공간", "Union 타입")
- 처음 나오는 전문 용어는 영문 병기 (예: "타입 단언(type assertion)")
- 일관된 용어 사용 유지

## 체크리스트

아이템 정리를 완료하기 전에 다음을 확인하세요:

- [ ] 파일명이 올바른 형식인가? (`src/section{N}/Item{N}.md`)
- [ ] 최상단에 인용문 형식의 핵심 요약이 있는가?
- [ ] 각 섹션이 번호로 구분되어 있는가?
- [ ] 모든 코드 예제가 ```ts로 시작하는가?
- [ ] 핵심 포인트가 ✅로 강조되어 있는가?
- [ ] 에러 발생 코드에 `// Error` 주석이 있는가?
- [ ] 마지막에 "핵심 정리" 섹션이 있는가?
- [ ] 전체적으로 읽기 쉽고 논리적인 흐름인가?

## 실행 절차

1. 입력된 아이템 정보에서 번호와 제목 파싱
2. 적절한 섹션 번호 결정 (아이템 1-10: section1, 11-20: section2, ...)
3. 파일 경로 생성: `src/section{N}/Item{번호}.md`
4. 위 템플릿에 맞춰 내용 작성
5. 파일 생성 완료 후 체크리스트 확인
```

## 사용 예시

### 입력
```
/ts-item 아이템11 타입 체크와 잉여 속성 체크 구분해서 사용하기
```

### 처리 과정
1. 아이템 번호: `11` 추출
2. 제목: `타입 체크와 잉여 속성 체크 구분해서 사용하기` 추출
3. 섹션 번호: `2` 결정 (11-20은 section2)
4. 파일 경로: `src/section2/Item11.md`
5. 템플릿에 맞춰 문서 작성 및 저장

### 다른 예시
```
/ts-item 아이템7 타입을 값의 집합이라고 생각하기
```
→ `src/section1/Item7.md` 생성

```
/ts-item 아이템25 비동기 코드에는 콜백 대신 async 함수 사용하기
```
→ `src/section3/Item25.md` 생성 (21-30은 section3)
